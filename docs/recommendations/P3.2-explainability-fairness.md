# Π3.2 — Explainability & fairness methodology (PerTouriSM)

**Scope:** Feature-grounded recommendation reasons (EL/EN), decision audit logging, gender/age fairness checks, and diversity/coverage metrics.  
**Feeds:** Π3.2 (recommendations quality) and [Π4.4 GDPR technical](../compliance/P4.4-gdpr-technical.md).  
**Stack:** `recommendations/` package + Recommendation Service (`recsvc`); mobile tours proxied via REST.

## 1. Reason schema

Each recommended stop includes `reasons` (1–3 items):

| Field | Meaning |
|-------|---------|
| `code` / `feature` | Scorer contribution id (`interest`, `proximity`, `weather_indoor`, …) |
| `text.el` / `text.en` | Human phrase from the feature→phrase map |

Implementation: `recommendations/explainability/` (`FeatureContribution` → `reasons_for_stop`). Contributions come from baseline weights (interest, proximity) plus context (time of day, weather, PM2.5, settlement, population) and hybrid CF/CB when active. Negative-only terms such as difficulty penalties are not surfaced.

See [MobileAPI.md](../MobileAPI.md) for the client contract (T4.2). Admin preview: recommendation tester shows locale-selected phrases.

## 2. Gender column (not a ranking feature)

`app_users.gender` is optional (`female` | `male` | `other` | `prefer_not_to_say`).  
`UserProfile` **omits** gender by design — rankings are gender-invariant by construction. Fairness eval verifies identical ordered sites when only gender would differ.

## 3. Fairness protocol

```bash
make rec.fairness
# → docs/recommendations/charts/fairness_summary.json
```

| Check | Method | Pass criterion |
|-------|--------|----------------|
| Gender parity | Same interests/age/context; gender labels unused by scorer | Identical rankings; demographic parity = 1.0 |
| Age group | `adult` vs `senior`, same interests | Document Jaccard / category parity; drift from difficulty filters is **justified** |

## 4. Diversity / coverage / popularity

```bash
make rec.diversity
# → docs/recommendations/charts/diversity_summary.json
```

Metrics in `recommendations/evaluation/metrics.py`:

- `catalog_coverage` — fraction of catalog seen across a persona batch
- `popularity_share` — share of recommendations in top-N popular sites
- `category_diversity` — unique categories per stop list

Thresholds are **observational** for Π3.2 (soft flag if top-10 popularity share ≥ 0.95). Live simulation: `make rec.sim` then `make rec.analyze`.

## 5. Decision audit logging

`recsvc` logs JSON lines:

```json
{"event":"recommend.decision","strategy_id":"balanced","weights":{...},"hybrid":false,"user_id":"...","origin":{"lat":...,"lng":...},"stops":[{"site_id":"...","score":...,"reason_codes":["interest","proximity"]}]}
```

No gender, email, or names. Retention: application log rotation (see Π4.4).

## 6. Reproduce

```bash
make migrate          # includes app_users.gender
make rec.fairness
make rec.diversity
make rec.up && make rec.sim   # optional live matrix
```
