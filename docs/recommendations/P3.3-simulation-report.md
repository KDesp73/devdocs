## Conclusions (engineering)

1. **Service split** isolates ranking latency and enables Redis caching without coupling chat/speech to recommend load.
2. **Context weights** (time/weather/mode) nudge indoor vs outdoor POIs; rain favors museums/culture; clear/hot favors nature/viewpoints.
3. **Feedback aliases** (`like`/`dismiss`/`visit`) map to existing event types so mobile DoD language and current DB schema stay aligned.
4. **Suggested routes** expose ordered stop LineString geometry for map clients.

## Improvements delivered in this iteration

- Dedicated Recommendation Service + Redis TTL cache (default 90s)
