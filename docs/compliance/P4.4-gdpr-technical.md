# Π4.4 — Technical GDPR / ΓΚΠΔ compliance note (PerTouriSM)

Technical documentation for the compliance report. Pilot: **Pelion (Πήλιο)**.

## 1. Controllers and systems

| System | Role |
|--------|------|
| FastAPI backend (`rest/`) | Personal data processing, Auth Service, consents, export/erase |
| PostgreSQL / PostGIS | Primary store (encrypted volume recommended in production) |
| Garage | Media for POIs (not visitor PII) |
| Admin Next.js | Staff CMS (cookie session) |
| External mobile app | Visitor UI (out of repo); consumes Mobile API |
| OpenAI-compatible LLM | Chat guide when `chat_llm` consent granted |
| Google / Apple | Identity providers for social login |

## 2. Data inventory and purposes (RoPA-lite)

| Data category | Examples | Purpose | Legal basis (pilot) | Retention |
|---------------|----------|---------|---------------------|-----------|
| Account identity | email, name, auth provider subject | Account, login | Consent (`account`) / contract | Until account erasure |
| Credentials | Argon2 password hash | Authentication | Contract | Until erasure |
| Profile preferences | interests, age group, **optional gender**, accessibility, children flag | Personalized tours; gender for fairness audit / profile only (**not** used in ranking) | Consent (`recommendations`) | Until erasure / withdraw |
| Tour feedback | event type, site IDs, zone geohash, city_id | Improve ranking / zone analytics | Consent (`analytics_zone`) | Anonymized on erase (user_id null); zone counters retained |
| Chat content | questions/answers, zone geohash | Site Q&A | Consent (`chat_llm`) | Deleted on erase |
| Auth tokens | JWT (client-held), hashed refresh tokens | Session security | Legitimate interest / contract | Refresh TTL / revoke |
| Zone aggregates | geohash × day counts | Operational analytics (no user_id) | Legitimate interest | Aggregate retention policy |
| Recommendation decision logs | opaque `user_id`, strategy/weights, stop ids, reason codes | Auditability / explainability (Π3.2) | Legitimate interest | Short retention (ops log rotation); **no** names, email, or gender |

**Not stored historically:** exact GPS tracks. Request-time coordinates used for ranking/RAG only; persisted as **municipality + coarse geohash** (~1–5 km).

## 3. Consent flows

Distinct purposes (API `GET/PUT /app-users/me/consents`):

1. `account` — store identity (email/social)
2. `recommendations` — use profile for tours
3. `analytics_zone` — store zone-level feedback / counters
4. `chat_llm` — send chat context to LLM

Mobile app must present **separate screens/toggles per purpose** before enabling the related feature. Withdrawal via `PUT` with `granted: false`. Enforced with HTTP 403 `CONSENT_REQUIRED`.

## 4. Subject rights

| Right | Implementation |
|-------|----------------|
| Access / portability | `GET /app-users/me/export` (JSON) |
| Erasure | `DELETE /app-users/me` — deletes chat + PII; anonymizes tour events; revokes tokens |
| Withdraw consent | `PUT /app-users/me/consents` |
| Staff-assisted | Admin `GET /app-users/{id}/export`, `DELETE /app-users/{id}` |

## 5. Security measures

- TLS at reverse proxy / load balancer
- Argon2 password hashing
- JWT access (short TTL) + rotating hashed refresh tokens with reuse detection
- Fernet encryption at rest for email/name; blind index for login lookup
- Rate limiting on auth endpoints
- OWASP Top 10 checklist; dependency scanning in CI (`pip-audit`, `npm audit`, Bandit, Dependabot)
- Secrets via environment / SSM — see [secrets.md](../security/secrets.md)

## 6. Third parties

| Party | Data shared | Safeguard |
|-------|-------------|-----------|
| LLM provider | Chat question, interests, municipality/zone, nearby site metadata | Requires `chat_llm`; no exact GPS |
| Google / Apple | id_token verified server-side; profile fields if provided | OAuth client IDs in env |
| Garage | Site media only | Separate credentials |

## 7. Minimization summary

Exact visitor location is **not** retained as a historical point. Analytics use **zone geohash + city**. Global recommendation bandit state is not per-user. Speech audio is not persisted.

### Optional gender on `app_users`

Nullable `gender` (`female` | `male` | `other` | `prefer_not_to_say`) supports profile completeness and offline fairness evaluation. It is **never** passed into `UserProfile` or the scoring pipeline. Erased with the account via `DELETE /app-users/me`.

### Recommendation decision logs

The Recommendation Service emits structured `recommend.decision` log lines (strategy id, bandit weights, opaque user id, stop ids, reason codes). Logs must not include gender, email, or names. Rotate with standard application log retention.
